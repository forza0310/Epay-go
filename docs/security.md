# 安全边界与上线条件

本文件记录设计约束；当前仅实现标注为“已实现”的部分，不代表已经通过生产安全审查。

## 当前已实现

- Go 1.26.4、本机工具链、零第三方 Go 依赖。
- 默认监听回环地址；HTTP 头、读取、写入、空闲超时；请求体读取上限 64 KiB。
- 响应 no-store、nosniff、no-referrer，框架阶段严格 CSP。
- 参数重复拒绝、兼容签名固定长度恒定时间比较、整数金额解析。
- 支付/管理能力未完成时明确失败，业务 readiness 为 503；没有默认密码或无鉴权管理功能。
- 不输出原始请求 URL、API key、私钥或完整插件配置。

## 正式业务接入前必须实现

1. 单管理员初始化走本地显式流程；密码采用成熟的自适应哈希。TOTP 绑定已经完成第一因素验证的短期会话，并限流、防重放。
2. 服务端可撤销会话，安全 Cookie、CSRF、登录节流和审计；后台操作与外部业务 API 使用不同凭证边界。
3. 密钥加密存储，主密钥由部署环境提供且不与数据库一起保存。备份需有单独受控的密钥恢复方案。
4. 支付宝请求签名、响应/通知验签、TLS 证书校验；网络超时与响应体上限，网关由可信配置固定。
5. 回调地址预登记；生产 HTTPS；拒绝 URL 凭证和不允许的端口，禁止内网、回环、链路本地、云元数据目标。
6. 校验 DNS 解析结果并在实际拨号时约束目标，避免只做一次字符串/域名检查；禁用自动重定向或逐跳重复验证。
7. 交易流水去重、金额/账户/入账状态核对、订单状态原子更新与 outbox 同事务。确认接口不得被前台直接调用。
8. 代理访问日志隐藏查询 key；数据库、备份和日志文件使用最小权限。应用不以 root 运行。
9. 选择 SQLite 驱动及其他依赖后固定版本，运行漏洞检查；正式发布重新核对 Go 1.26.4 的安全状态，处理相关已知问题。
10. 对实际支付闭环进行失败恢复、重放、越权、金额篡改和备份恢复验证，不以当前构建成功代替。

## 协议遗留边界

ZPAY 查询接口通过 URL 传 key，签名采用 MD5。这些是有意隔离的兼容约束，不是新鉴权协议模板。使用 HTTPS、日志脱敏、固定权限、可轮换凭证和受控来源降低暴露。重复订单由业务幂等规则处理；原协议没有时间戳，不宣称已经具备完整请求时效校验。

## 插件信任

编译式插件与主程序权限相同。新增插件需要代码审查及依赖核对。签名包或接口约束不能把恶意代码自动变成安全代码；若未来接纳第三方动态插件，再设计操作系统级权限隔离。
