# 安全边界与上线条件

当前覆盖第一步管理员和持久化基础，不代表支付系统已具备生产收款条件。使用用户指定的 Go 1.27.3；依赖固定版本，检查结果见 verification.md，不能仅凭版本号宣称没有漏洞。

## 已实现的边界

- 受保护后台路由统一使用 requireLogin 包装 adminHandler；会话检查失败时不会执行业务函数，成功后显式传入 adminSession。修改数据仍检查来源与表单 CSRF，不能只依赖 Cookie。新增后台接口须遵循此注册方式。

- 默认回环监听；读取头 5 秒、读 10 秒、写 15 秒、空闲 60 秒，头上限 16 KiB，请求体上限 64 KiB。
- 后台 POST 单一表单来源，拒绝查询参数、重复和未知字段；Origin 与 Fetch Metadata 来源检查。没有 Origin 的非浏览器请求仍必须提供有效 CSRF。
- 响应 no-store、nosniff；后台使用 Referrer-Policy: same-origin，保留同源 HTML 表单的真实 Origin，跨源不发送 Referer；其他接口继续使用 no-referrer，保护支付查询凭证。来源校验仍拒绝 Origin: null；CSP 禁止脚本、框架嵌入和外部资源，仅允许同源图片和同源表单。
- 单管理员首次通过网页初始化，允许远程访问且按用户选择不设置安装凭证；首个完成初始化者获得管理员身份，完成后入口关闭。密码 PBKDF2-SHA256，600,000 次迭代，随机 16 字节盐，32 字节摘要，长度 10–1024 UTF-8 字节。
- TOTP 使用 SHA-1 HMAC、6 位、30 秒，允许前后各一周期；单调更新已用周期，与会话创建原子提交。密码和动态码都通过后才创建会话，旧单因素记录不能登录。
- TOTP 种子 AES-256-GCM 加密；首次绑定在网页展示，仅用于用户添加验证器；二维码在服务端内存生成，不使用第三方服务。图片入口只接受有效初始化 Cookie、拒绝已初始化状态，不缓存、不落盘，URL 不含种子。待绑定种子以进程临时密钥加密存入 HttpOnly Cookie，绑定 CSRF 与 10 分钟有效期，重启失效。reset-totp 要求主密钥、已有密码和新动态码，原子撤销全部会话。
- 32 字节随机会话/CSRF 令牌只存 SHA-256 摘要，会话固定 12 小时；服务器验证有效期与撤销状态，重启保留会话。
- Cookie 默认 Secure、HttpOnly、SameSite=Strict、Path=/，使用 __Host- 前缀且无 Domain。开发模式可关闭 Secure，但仅允许数字回环监听；不得经代理/隧道对外暴露开发模式。
- 登录 CSRF 采用带进程 HMAC 签名及 10 分钟有效期的双提交令牌，防 Cookie 注入；登录前表单在服务重启后失效。登录后 CSRF 与数据库会话绑定。
- 登录按直连来源限制每 15 分钟 5 次尝试，全账户 20 次，超额锁定 15 分钟，拒绝时返回剩余等待时长；成功登录清除该来源计数，全局计数不清除；不信任 X-Forwarded-For。昂贵密码计算最多并发 2 个，过期会话和限流记录在后续登录时清理。全局额度也会统计被来源限流拒绝的尝试，属于有意的保守限制。HTTP 429 单独提示本次请求时的剩余等待时间，Retry-After 采用相同的向上取整秒数；密码计算并发满时建议等待 1 秒，不误报为锁定 15 分钟。
- SQLite 数据目录必须私有（0700），拒绝末级目录/数据库符号链接；打开 SQLite 前创建/限制数据库文件权限至 0600。WAL/SHM 位于私有目录，父目录由可信部署者控制，不能置于不可信用户可替换的目录层级。单实例、单连接、WAL、外键、busy timeout、synchronous FULL。
- 嵌入迁移按版本事务执行，拒绝未知迁移版本；初始化、登录防重放、TOTP 恢复和配置审计均有事务边界。
- 配置使用 data/master.key 中的 32 字节主密钥及随机 nonce 的 AES-GCM；附加认证数据区分 channel:<id>、admin:totp:1、system:master-key。密文格式为 nonce + 密文/认证标签，当前尚无轮换工具。启动校验主密钥与数据库匹配。
- 管理页面只读取元数据，不返回配置明文；编辑留空在 SQL 中保留现有密文。已编译插件白名单、ID/名称长度和 JSON 对象检查在领域服务中执行。
- 审计表记录初始化、成功登录、退出、TOTP 重置及通道变更的类型、时间和对象 ID，不包含密码、种子、Cookie 或插件配置。失败尝试由持久化限流表记录计数；目前无失败详情历史或审计查询页面。

## 部署与恢复要求

启动工作目录的 .env 可提供本地配置；已有进程环境变量优先，程序不改写全局环境。配置文件必须来自可信项目目录；EPAY_MASTER_KEY 不再参与配置加载，.env 已被 Git 忽略。解析不执行 shell 或变量插值，限制文件大小，错误不回显配置值。初始化和服务启动使用同一套加载规则。

生产后台必须使用 HTTPS；反向代理禁用对完整请求体、Cookie、URL 查询凭证的记录。Secure=true 表示部署者承诺提供 HTTPS，程序不能验证代理外部链路是否安全。代理后的登录限流共享代理地址，不自动解析可伪造的转发头。

首次安装允许未认证的网页访问者创建唯一管理员，不增加安装令牌；保留同源、CSRF、有效期与密码派生并发限制。本地恢复须停服，不支持多实例并行操作。主密钥固定在工作目录 data/master.key，空数据库首次自动生成并原子发布，目录 0700、文件 0600；原密钥缺失或损坏时禁止为已有加密状态重建密钥。备份包含配套密钥，整个默认 data 目录被获取即失去磁盘加密保护。数据库停服复制或用 SQLite 在线备份；不能在 WAL 写入时仅复制 .db。持有数据库与主密钥即可解密敏感配置，磁盘加密不防进程或主机被攻陷。Go 不保证内存中凭证立即擦除。

没有网页找回、默认密码、通用恢复码或密码丢失绕过；主密钥丢失无法解密。生产需保护终端滚动记录，TOTP 手工绑定信息不可共享。主机保持时间同步；单调周期防重放意味着时钟倒退时可能暂时拒绝登录。

## 后续业务必须完成

1. 支付宝请求签名、响应/通知验签、TLS 校验、网络超时和响应大小限制；固定可信网关。
2. 回调地址预登记，生产 HTTPS，限制端口、URL 凭证、内网/回环/链路本地/云元数据地址；在 DNS 解析和实际拨号时校验，禁止随意跟随重定向。
3. 流水去重、账户/方向/金额/状态核对；订单确认与通知 outbox 原子提交，付款浏览器不能确认到账。
4. 通知重试、异常到账审计及备份恢复、重放、越权、金额篡改验证。
5. 支付插件具体字段校验、API 凭证管理、生产依赖与工具链安全复核。当前 JSON 保存不是支付宝验证。

## 协议与插件边界

ZPAY 查询通过 URL 传 key，兼容签名采用 MD5，仅限既定协议；必须使用 HTTPS、日志脱敏和受控调用来源。原协议没有时间戳，不能宣称已经提供完整请求时效校验。余额、退款和其他未实现支付能力明确返回错误。

插件随程序构建，与主程序同权限，不是安全沙箱。只接受审查后编译的代码，不支持上传源码执行；若未来引入第三方动态插件，必须重新设计隔离。
