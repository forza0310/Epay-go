# 关键设计决策

## ADR-001：Go 与工具链

状态：用户指定。使用本机 Go 1.27.3，设置 GOTOOLCHAIN=local，禁止构建时自动下载其他版本。

理由：遵循用户明确的开发版本选择。代价：固定版本不会自动跟随安全更新；正式发布前需核对已知漏洞与修复要求，再由用户决定版本变更，不能宣称所有最新安全补丁已包含。

## ADR-002：单管理员、直接收款

状态：用户指定。唯一管理员管理自己的多个通道，保留 PID 仅用于外部协议兼容。

理由：业务不涉及平台结算。省去多租户、余额账户、手续费和分账。仍需保存到账流水，用于审计与防重复发货。

## ADR-003：编译式插件与功能移植

状态：已确认。插件随主程序编译发布；第一个插件为 alipaycode 的 Go 移植。构建时扫描约定目录，生成显式导入和构造代码，由 builtin.NewRegistry 统一装配。新增插件不再修改 app.New。

理由：保留收款流程，降低原 PHP 全局状态和运行环境耦合。生成代码保留静态类型检查、可审查的导入关系与显式构造，不依赖 init 自注册和可变全局注册表。代价：新增插件需要重新生成、构建和发布；生成文件须与插件源码一起提交，普通 go build 不自动执行生成。不能直接运行原 PHP 文件。只有明确需要动态安装时，再评估进程隔离的插件协议。

## ADR-004：标准库 HTTP、SQLite、单进程

状态：已确认。使用 net/http；后台及收银台计划采用 html/template；SQLite 单实例存储，内置采集和通知 worker。

理由：当前范围不需要 Redis、消息队列或大型框架。代价：SQLite 写事务需短且受控，多实例运行不在本阶段范围。使用 modernc.org/sqlite v1.62.0 纯 Go 驱动，固定版本并检查漏洞；迁移以嵌入的 migrations/*.sql 为唯一来源，向前升级，不提供自动降级。

## ADR-005：ZPAY 协议隔离

状态：用户要求兼容，差异在 API 文档明确。外部 MD5、PHP 路径与 DTO 仅存在于协议/HTTP 层；内部保持金额与状态强类型。

理由：兼容调用方，不让历史协议决定内部模型。MD5 不扩散到密码、会话或新设计的加密逻辑。ZPAY 平台余额及专属小程序不具有可直接复制的业务实体。

## ADR-006：余额接口和预登记回调

状态：已确认。`act=balance` 不实现并返回错误；后台预登记允许的 notify_url 和 return_url，支付请求只能选择匹配地址。

理由：系统不托管平台余额，不返回误导性的累计到账金额；同时控制服务端通知的访问范围。代价：比任意回调 URL 更严格；新增自有业务地址需管理员登记。

## ADR-007：仅为高价值边界保留测试

状态：遵循用户工程要求。测试聚焦金额、签名、身份认证、加密与持久化一致性，不按文件数量凑覆盖率。

理由：验证真实失败模式，不为每个结构体、getter 或占位函数增加测试。后续支付确认、鉴权、恢复和幂等属于高风险逻辑，应随实际实现增加必要测试。

## ADR-008：网页首次初始化与双因素登录

状态：用户确认首次启动通过网页创建管理员，允许远程初始化且不增加安装凭证。服务检查持久化管理员状态；未初始化时登录页跳转 /admin/setup，设置并确认密码、手工绑定 TOTP 并验证动态码后原子创建唯一管理员。创建成功后初始化入口关闭；不提供网页重置入口。远程部署使用 HTTPS 反向代理。

初始化表单受同源检查、CSRF 与 10 分钟有效期保护。TOTP 待绑定种子保存在进程随机密钥加密的 HttpOnly Cookie 内，绑定页展示种子，不使用第三方二维码服务。重启后未提交的表单失效，已创建管理员不受影响。密码派生限制并发；数据库保证并发提交最多创建一名管理员。代价：首次初始化没有身份门槛，首个完成初始化的访问者成为管理员，这是用户明确接受的部署边界。

密码使用 PBKDF2-SHA256（600,000 次、16 字节盐、32 字节摘要），TOTP 使用 RFC 6238 的 SHA-1、6 位、30 秒周期，允许前后各一周期偏差；已用周期不得重放。登录必须同时验证两种因素，才创建 12 小时会话。本地 reset-totp 要求原密钥文件、已有密码和新动态码，原子撤销全部会话。

## ADR-009：最小通道后台与加密边界

状态：用户确认第一步提供后台页面。支持新增、修改和启停已编译插件的通道；配置采用 JSON 对象输入，敏感配置只写不回显，修改时留空保留原密文。第一步只验证通用格式，不把保存成功解释为支付宝配置验证成功。第三步接入插件字段校验及真实调用。

使用 data/master.key 中的 32 字节主密钥和 AES-256-GCM；通道与 TOTP 使用不同的附加认证数据命名空间。数据库存储加密校验值，启动时拒绝错误主密钥。主密钥文件与数据库均需备份，不能每次启动重新生成；轮换工具暂未提供。

## ADR-010：自动加载工作目录 .env

状态：用户明确要求直接读取启动工作目录的 .env，不查找父目录、go.mod 或可执行文件目录。已有环境变量优先于文件值，文件值优先于默认值。显式空环境变量同样优先，不隐式回退到文件值；主密钥不参与此配置流程。

理由：让终端与 IDEA 共用配置，同时保留部署环境覆盖能力。使用标准库实现有限的单行语法，不执行 shell、不插值变量，不将密钥写入进程全局环境。文件缺失允许环境变量部署；文件存在但无法读取、重复定义或格式错误时明确失败，错误不回显值。代价：不提供完整 shell/dotenv 扩展语法；相对数据库路径仍以启动工作目录为准，加载文件不改变工作目录。

## ADR-011：自动持久化主密钥

状态：用户指定主密钥只从启动工作目录的 data/master.key 读取，EPAY_MASTER_KEY 不再作为配置来源；即使自定义数据库路径，密钥路径也不改变。空数据库首次启动自动生成 32 字节随机主密钥，以 Base64 文本保存，目录 0700、文件 0600，不回显到日志或网页。

临时文件写入并同步后，通过不覆盖已有目标的硬链接发布，再同步目录；密钥落盘后才写数据库校验值。已有校验记录、管理员或通道时若文件丢失，拒绝重新生成；格式错误、权限不安全或密钥不匹配同样拒绝启动。崩溃后可以复用已经保存的密钥，不会自动替换。仅支持单实例。用户明确要求清空本地旧数据库与旧主密钥，本次不自动迁移旧环境变量中的密钥。

理由：省去首次安装的命令行密钥操作。代价：密钥和默认数据库在同一目录，整个 data 目录泄漏即可解密配置；目录权限不能抵御主机失陷。备份必须包含匹配的密钥，密钥丢失无恢复绕过。

## ADR-012：TOTP 本地二维码

初始化页同时提供扫码和手工绑定。使用标准 otpauth://totp/epay:admin URI，issuer=epay、SHA1、6 位、30 秒，与现有 TOTP 校验一致。服务器通过固定版本 github.com/skip2/go-qrcode v0.0.0-20200617195104-da1b6568686e 在内存生成 PNG；该库仅编码图片，无传递模块依赖，不访问外部服务，不自行实现二维码纠错算法。引入前查询 Go 官方漏洞模块索引，未发现该模块公告。

图片由 /admin/setup/qr.png 提供，仅接受有效初始化 Cookie 并检查管理员尚未创建。URL 不携带绑定密钥，响应禁止缓存且限制同源嵌入；初始化成功或 Cookie 失效后拒绝读取。CSP 仅增加同源图片许可，保持脚本和外部资源禁用。代价是增加一个固定版本的编码依赖，后续仍需随发布检查安全公告。

## ADR-013：后台路由统一检查登录

受保护的后台处理函数统一使用 adminHandler 类型，比标准 HTTP 处理函数多接收一个 adminSession 参数。路由注册时通过 requireLogin 包装：先检查登录会话和 CSRF Cookie，成功后将验证过的会话信息传给业务函数；失败时直接返回响应，不执行后续业务。

选择显式参数而不使用请求 context，便于查看处理函数需要哪些会话信息。该类型不能直接传给 HandleFunc，漏掉包装会导致编译错误；新增后台功能仍须按约定使用此类型。公开登录、首次初始化、健康检查和支付占位接口不使用管理员登录中间件，分别遵守各自的访问规则。

业务处理函数不再重复检查登录；保存通道和退出登录仍检查表单来源及提交的 CSRF 令牌，Cookie 检查不能代替这一步。会话数据只在 HTTP 层传递，不记录到日志或返回给非认证请求。
