# epay

单管理员、自用收款、编译式插件的 Go 服务。当前为**第一步：运行与管理员基础**，待用户审核后才继续支付业务。兼容目标以 [ZPAY 文档](https://z-pay.cn/doc.html#d1) 为依据。

## 当前状态

- 已实现：SQLite 事务迁移、单管理员网页初始化、密码与 TOTP 登录、持久化可撤销会话、CSRF 与登录限流、收款通道新增/修改/启停、敏感配置 AES-256-GCM 加密。
- 已有基础：插件注册、协议 DTO、MD5 兼容签名、整数金额、订单及到账模型。
- 未实现：ZPAY 下单/查询、支付宝调用、账单采集、到账确认、通知投递、收银台。`alipaycode` 当前仅有插件骨架；保存或启用配置不代表已可收款。
- `/admin/` 已提供后台；支付接口及 `act=balance`、退款返回 HTTP 501。`/readyz` 仍为 503，目前不能用于真实收款。

## 构建与首次初始化

使用用户指定的 **Go 1.27.3**，设置 `GOTOOLCHAIN=local`，不自动下载工具链。第三方依赖固定在 `go.mod`/`go.sum`。

```sh
make build
./bin/epay
```

首次启动时，程序自动生成主密钥并保存到**启动工作目录的 `data/master.key`**。无需执行 `keygen` 或 `init-admin`，不再读取 `EPAY_MASTER_KEY`；`.env` 只配置监听地址、数据库路径和 Cookie 模式。密钥不出现在页面或日志中，文件权限为 `0600`，目录为 `0700`，重启复用同一个文件。

打开 `/admin/login`（或站点根路径），未初始化时自动进入 `/admin/setup`。在页面输入并确认密码（10–1024 UTF-8 字节），使用密码管理器或验证器扫描页面二维码（也可手工添加绑定密钥）：账户 `epay / admin`，基于时间、SHA-1、6 位、30 秒。输入动态码后创建管理员；成功后等待下一动态码周期再登录。表单有效期 10 分钟，过期或服务重启后需刷新页面并重新绑定。

支持通过 HTTPS 远程初始化，不设置安装凭证；首个完成初始化的访问者成为唯一管理员。创建成功后初始化入口关闭，并发请求也不能创建第二名管理员。没有默认账号密码，也没有网页重置入口。

数据库默认 `./data/epay.db`，可用 `EPAY_DB_PATH` 调整；密钥固定为工作目录的 `data/master.key`，不随数据库路径改变。数据库目录须私有（0700）、文件为 0600。已有数据或主密钥校验记录时，密钥文件丢失会拒绝启动，不会自动生成替代密钥；密钥损坏、权限不安全或与数据库不匹配也会报错。恢复旧数据库须将原 Base64 主密钥保存为此文件并限制权限，不会自动迁移旧 `.env` 中的密钥。

## 运行与管理

生产部署保持安全 Cookie 默认值，在受控 HTTPS 反向代理之后运行：

```sh
./bin/epay
```

本地仅通过 HTTP 调试时：

```sh
EPAY_ADDR=127.0.0.1:8080 EPAY_COOKIE_SECURE=false ./bin/epay
```

不安全 Cookie 模式仅允许数字回环监听地址；不要将此模式经代理或隧道暴露到公网。访问 `/admin/login`，输入密码与动态码。会话有效期 12 小时，重启继续有效，退出和本地恢复会撤销服务端会话。

后台可新增、修改和启停通道。当前插件为 `alipaycode`，配置填写非空 JSON 对象；本阶段只进行格式检查和加密保存，第三步接入支付宝配置字段及连接验证。已保存的配置不回显，编辑时留空保留；更换账户或插件必须重新提交配置。启停通过编辑页的状态选项完成。

登录限制：每个直连来源 15 分钟最多 5 次尝试，账户全局最多 20 次；超过限制锁定 15 分钟；成功登录清除该来源计数，全局计数不清除。代理头不作为来源依据，反向代理后的所有请求共用代理地址额度。动态码不能重复使用，短时间重新登录须等待下一个周期。主机与验证器须保持准确时间。触发限流时页面会明确显示剩余等待时长；等待后刷新登录页再提交，避免使用过期表单。

程序自动读取启动工作目录的 `.env`，正常启动和 `reset-totp` 均生效。可参考 `.env.example` 创建文件，无需填写主密钥；`.env` 已被 Git 忽略。

配置优先级为 **已有进程环境变量（包括 IDEA 运行配置）→ `.env` → 默认值**。显式设置的空环境变量也不会被文件覆盖；若希望使用 `.env` 中的值，请删除 IDEA 中对应的环境变量条目。主密钥文件不参与环境变量优先级。

只读取启动工作目录下的 `.env`，不向父目录查找，不依赖 `go.mod` 或可执行文件位置。IDEA 的 Working directory 应设置为存放 `.env` 的目录，例如项目根目录。数据库相对路径也以工作目录为准。

支持 `NAME=value`、可选 `export` 前缀、空行、注释、单行单双引号；双引号可使用 `\n`、`\t`、`\"`、`\\` 等转义。未加引号的行尾注释须与值用空白隔开。支持 UTF-8 BOM 和 CRLF；不支持多行值、变量插值或 shell 命令执行，例如 `$(cat ...)` 会被当作普通文本。文件上限 64 KiB，重复变量和语法错误会阻止启动，错误仅报告行号和原因，不输出变量值。文件不存在时仍可完全通过环境变量运行。

`.env` 作为配置读取的后备来源，不改写进程的全局环境；修改后需要重启程序。`EPAY_ADDR` 默认 `127.0.0.1:8080`。

## 验证器丢失与备份

停止服务，保留原 `data/master.key`，在相同工作目录的本机终端执行：

```sh
./bin/epay reset-totp
```

输入现有管理员密码，绑定新密钥并验证新动态码。成功后所有旧会话失效，旧验证器不可再用；失败不改变原绑定。没有网页找回和通用恢复码。密码或主密钥丢失没有内置绕过方式。

备份时停止服务再复制完整数据目录，或使用 SQLite 在线备份工具；不要在 WAL 写入期间只复制 `.db` 文件。恢复需配套的 `data/master.key`，自定义数据库路径时也要备份该文件。密钥与默认数据库同目录，整个 data 目录泄漏即可解密敏感数据，备份应限制访问。密钥轮换工具和备份自动化不在本阶段。

## 构建与检查

```sh
make build    # 自动发现插件，再构建 bin/epay
make check    # 自动发现插件，再执行 go vet ./... && go test ./...
```

插件通过构建时自动发现注册。新增或删除 `internal/plugin/<name>/` 插件包后执行 `make build`，无需修改启动代码。生成文件须一并提交；`make check-generated` 可检查是否过期。直接使用 `go build` 前须执行 `make generate`，详细约定见 [插件设计](docs/plugins.md)。

测试集中覆盖插件发现、签名、金额、双因素、防重放、会话撤销、加密及 HTTP 鉴权等高风险边界。实际执行结果和依赖扫描范围见 [验证记录](docs/verification.md)。

管理员服务的职责、安全规则与验证范围见 [管理员服务](docs/admin.md)。
